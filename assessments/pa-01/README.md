# PA‑1 — تشخيص المسار وإثبات الإصلاح
# Pipeline Diagnosis and Verification

**المدة:** 30 دقيقة · **نوع العمل:** فردي · **البيانات:** اصطناعية

## السيناريو

استلمت جزءًا مصغرًا من مسار «بيان». تبدو مخرجاته معقولة، لكن ثلاث canaries تكشف عدم اتساق بين التدريب والخدمة، ومقياس NER غير مناسب، وعقد متجه الاستعلام غير مكتمل.

## ابدأ

1. انسخ هذا المجلد إلى مستودعك.
2. شغّل الأمر الآتي **قبل التعديل**؛ ظهور ثلاث حالات `FAIL` متوقع في starter ولا يعني أن مستودع الدورة معطوب:

```bash
python assessments/pa-01/check_pa1.py
```

3. اقرأ [`starter_buggy.py`](starter_buggy.py)، وشخّص السبب قبل التعديل.
4. أصلح الدوال فقط؛ لا تعدل [`check_pa1.py`](check_pa1.py).
5. أعد التشغيل حتى تظهر `PA1_CANARIES=PASS`.

## المطلوب تسليمه

- `starter_buggy.py` بعد التصحيح.
- `PA1_DIAGNOSIS.md` وفق [القالب](PA1_DIAGNOSIS_TEMPLATE.md).
- مخرج الأمر الذي يثبت نجاح canaries، مع commit hash.

## معيار التصحيح

| البعد | الوزن | الدليل المتوقع |
|---|---:|---|
| التشخيص | 40% | يحدد سبب كل عطل وأثره، لا رقم السطر فقط |
| الإصلاح | 40% | يعيد عقد train/serve، entity-level NER، وL2 query contract |
| التحقق | 20% | canaries خضراء + مخرجات + commit قابل للفحص |

**ممنوع:** حذف assert، تغيير القيمة المتوقعة، أو hard-code نتيجة canary. يراجع المقيم الشرح والكود معًا.
