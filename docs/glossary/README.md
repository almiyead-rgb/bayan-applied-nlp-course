> للشرح والمراجعة اليومية ابدأ بقاموس اليوم، وللبحث عن مصطلح من أي يوم استخدم الجدول العام التالي.

| المصطلح العربي | English | تعريف مبسط | ملاحظة تقنية |
|---|---|---|---|
| معالجة اللغات الطبيعية | Natural Language Processing (NLP) | جعل الحاسوب يحلل اللغة أو ينتج مخرجات منها | مجال يجمع اللغة والحوسبة والتعلم الآلي |
| متن/مجموعة نصوص | Corpus | نصوص نجمعها للدراسة أو التدريب | يجب توثيق المصدر والترخيص والتقسيم |
| محرف | Character | رمز واحد في النص | قد يتكون الرمز المرئي من أكثر من Unicode code point |
| يونيكود | Unicode | معيار تمثيل الحروف | UTF-8 ترميز شائع لرموز Unicode |
| ترميز نصي | Encoding | تحويل الرموز إلى bytes والعكس | خطأ encoding قد يفسد العربية دون خطأ واضح |
| تنميط النص | Normalisation | توحيد أشكال مختارة من النص | قرار مرتبط بالمهمة والنموذج وقد يفقد معلومات |
| ملف تنميط | Normalisation profile | وصف مسمى ومُرقّم لتحويلات النص | يجب أن يتطابق في التدريب والفهرسة والتقييم والخدمة |
| إخفاء البيانات | PII masking | استبدال البيانات الحساسة بعلامات | يجب أن يحدث قبل logging أو النشر |
| وحدة نصية | Token | جزء يعالجه tokenizer كوحدة | قد يكون كلمة أو subword أو رمزًا |
| تجزئة/ترميز | Tokenisation | تقسيم النص وتحويل الوحدات إلى IDs | tokenizer يجب أن يطابق checkpoint |
| مفردات | Vocabulary | قائمة الوحدات التي يعرفها tokenizer | لكل token رقم خاص داخل checkpoint |
| وحدة تحت كلمية | Subword | جزء من كلمة | تساعد في الكلمات النادرة لكنها تطيل التسلسل |
| رموز خاصة | Special tokens | وحدات مثل CLS وSEP وPAD | معناها ومكانها يعتمدان على النموذج |
| خصوبة الترميز | Token fertility | متوسط tokens الناتجة لكل كلمة | ارتفاعها يزيد الطول والحوسبة وخطر truncation |
| قطع | Truncation | حذف ما يتجاوز الحد | قد يحذف المعلومة المهمة ويجب قياس أثره |
| حشو | Padding | إضافة وحدات حتى تتساوى الأطوال | dynamic padding يقلل الهدر غالبًا |
| لصيقة | Clitic | جزء قصير يلتصق بالكلمة | مثل الواو والباء؛ مهم لمحاذاة NER العربية |
| تنوع عربي | Arabic variant | سجل أو شكل لغوي مثل MSA أو Gulf | الوسم المقدم يدويًا لا يساوي تنبؤ لهجة |
| عربيزي | Arabizi | كتابة العربية بحروف لاتينية وأرقام | يحتاج مسار تحويل وتقييم مستقلًا؛ heuristic ليست مصنفًا |
| جذر | Root | أصل صرفي مشترك | ليس بديلًا دائمًا للـlemma |
| لِمّة/صيغة معجمية | Lemma | الشكل القاموسي للكلمة | يحتاج تحليلًا صرفيًا وسياقًا أحيانًا |
| اشتقاق مبسط | Stemming | إزالة زوائد بقواعد تقريبية | أسرع لكنه قد ينتج شكلًا غير معجمي |
| تضمين | Embedding | متجه أرقام يمثل وحدة لغوية | قرب المتجهات قد يعكس تشابهًا تعلمه النموذج |
| تضمين سياقي | Contextual embedding | تمثيل يتغير حسب الجملة | كلمة واحدة قد تحصل على متجه مختلف حسب السياق |
| تشابه جيبي | Cosine similarity | يقارن اتجاه متجهين | عند FAISS inner product يجب تطبيع الجهتين |
| تطبيع L2 | L2 normalisation | يجعل طول المتجه يساوي واحدًا | يطبق على corpus وquery قبل IndexFlatIP لمحاكاة cosine ranking |
| انتباه | Attention | يوزع وزنًا على معلومات مرتبطة | الأوزان ناتجة من Q وK وتستخدم مع V |
| انتباه ذاتي | Self-attention | tokens الجملة تنتبه لبعضها | التعقيد الأساسي تربيعي في طول التسلسل |
| استعلام | Query (Q) | ما الذي يبحث عنه الموضع؟ | إسقاط خطي من hidden state |
| مفتاح | Key (K) | كيف يعلن الموضع عما لديه؟ | يدخل في score مع Query |
| قيمة | Value (V) | المعلومة التي ستُجمع | تجمع موزونة بعد softmax |
| انتباه متعدد الرؤوس | Multi-head attention | عدة مساحات انتباه بالتوازي | تسمح بعلاقات مختلفة ثم تدمج المخرجات |
| محوّل | Transformer | معمارية تعتمد attention وطبقات feed-forward | قد تكون encoder أو decoder أو الاثنين |
| مُرمِّز | Encoder | يبني تمثيلات للسياق المدخل | BERT من عائلة encoder |
| نقطة تحقق | Checkpoint | أوزان وإعدادات محفوظة | يجب توثيق الاسم والنسخة وtokenizer |
| تدريب مسبق | Pretraining | تعلم عام على نصوص كبيرة | يسبق التكييف لمهمة محددة |
| ضبط دقيق | Fine-tuning | تحديث النموذج على مهمة وبيانات محددة | يحتاج split وتقييمًا يمنع leakage |
| خط أساس | Baseline | حل بسيط نقارن به | لا قيمة لتعقيد إضافي بلا مقارنة |
| تصنيف النص | Text classification | اختيار label للنص | استخدم macro-F1 عند أهمية الفئات بالتساوي |
| كيان مسمى | Named Entity | اسم شخص/مكان/منظمة ونحوها | المهمة تسمى NER وتقاس على entity-level |
| مخطط BIO | BIO scheme | B بداية وI داخل وO خارج كيان | يحتاج محاذاة بعد subword tokenisation |
| محاذاة الوسوم | Label alignment | ربط labels بالكلمات/subwords | special/continuation tokens قد تستخدم -100 في loss |
| إجابة استخراجيّة | Extractive QA | اختيار span من سياق | يجب أن يدعم no-answer عندما لا توجد إجابة |
| لا توجد إجابة | No-answer | قرار الامتناع عن span | يمنع استخراج جواب بالقوة |
| بحث دلالي | Semantic search | استرجاع نصوص بالمعنى | يعتمد embedding وفهرسًا وتقييم queries |
| مُرمِّز ثنائي | Bi-encoder | يرمز query والوثيقة منفصلين | سريع ويسمح بحساب embeddings مسبقًا |
| مُرمِّز تقاطعي | Cross-encoder | يقرأ query والمرشح معًا | أدق غالبًا لكنه أغلى لكل زوج |
| إعادة ترتيب | Re-ranking | إعادة ترتيب مرشحين بعد الاسترجاع الأولي | يشغل cross-encoder على top-k صغير لا corpus كامل |
| FAISS | FAISS | مكتبة لفهرسة المتجهات والبحث | IndexFlatIP خط أساس exact بعد L2 normalisation |
| فهرس متجهي | Vector index | بنية تبحث في embeddings بسرعة | يجب أن يطابق النموذج والبعد والمعالجة والبيانات |
| بيان الفهرس | Index manifest | ملف يصف كيف بُني الفهرس | يسجل model/profile/dataset/dimension/vector count |
| مجموعة التدريب | Training set | بيانات تحديث النموذج | لا تستخدم لتقدير الأداء النهائي |
| مجموعة التحقق | Validation set | بيانات اختيار القرارات | تستخدم للضبط وتحليل الأخطاء |
| مجموعة الاختبار المجمدة | Frozen test set | تقييم نهائي لا يوجّه التطوير | لمسها أثناء tuning يسبب leakage |
| تسرب البيانات | Data leakage | وصول معلومة لا ينبغي للنموذج معرفتها | يرفع القياس ويضعف التعميم الحقيقي |
| الدقة الإيجابية | Precision | كم تنبؤًا إيجابيًا كان صحيحًا؟ | TP/(TP+FP) |
| الاستدعاء | Recall | كم حالة صحيحة اكتشفناها؟ | TP/(TP+FN) |
| درجة F1 | F1 score | توازن توافقي بين precision وrecall | يتأثر بطريقة التجميع |
| Macro-F1 | Macro-F1 | متوسط F1 للفئات بالتساوي | يكشف ضعف الفئات الصغيرة أفضل من accuracy وحدها |
| مصفوفة الالتباس | Confusion matrix | أين تختلط الفئات؟ | صفوف/أعمدة التوقع والحقيقة يجب توضيحها |
| التطابق التام | Exact Match (EM) | هل الجواب مطابق بعد قواعد محددة؟ | مقياس QA صارم |
| الاستدعاء عند k | Recall@k | هل ظهر الصحيح ضمن أول k؟ | مقياس استرجاع يحتاج relevance labels |
| متوسط الرتبة المقلوبة | MRR | يكافئ ظهور أول إجابة صحيحة مبكرًا | متوسط 1/rank لأول نتيجة صحيحة |
| تحليل الأخطاء | Error analysis | قراءة الأخطاء وتصنيف أسبابها | يجرى على validation لا frozen test |
| شريحة تقييم | Evaluation slice | جزء محدد مثل اللغة أو الفئة | يمنع المتوسط العام من إخفاء الضعف |
| فاصل ثقة | Confidence interval (CI) | نطاق يعبر عن عدم يقين التقدير | اتساعه على عينة صغيرة لا يختفي بزيادة مرات الحساب فقط |
| Bootstrap | Bootstrap | إعادة أخذ عينات مع الإرجاع لتقدير عدم اليقين | المقارنة بين نموذجين تستخدم resamples زوجية متطابقة |
| مقارنة زوجية | Paired comparison | مقارنة إصدارين على الأمثلة نفسها | CI لفرق يشمل الصفر لا يدعم ادعاء تفوق اتجاهي |
| اختبار سلوكي | Behavioural test | مثال يفحص سلوكًا لغويًا محددًا | يكمل metric العام ويصبح regression test عند الإصلاح |
| تصنيف الأخطاء | Error taxonomy | وسوم بشرية لأسباب الأخطاء | فرضيات قابلة للاختبار وليست حقيقة آلية |
| شريحة صغيرة | Small slice | مجموعة تقييم قليلة الأمثلة | توسم `SMALL_SLICE` وتفسر بحذر بدل إخفائها |
| استدلال | Inference | تشغيل النموذج لإنتاج تنبؤ | يختلف عن التدريب في الذاكرة والهدف |
| زمن الاستجابة | Latency | زمن طلب واحد أو دفعة | اذكر p50/p95/p99 والجهاز والدفعة |
| إحماء | Warm-up | تشغيلات تهيئة لا تدخل في القياس | يمنع تحميل النموذج أو compilation الأول من تشويه المقارنة |
| الوسيط | p50 latency | قيمة نصف الطلبات أسرع منها ونصفها أبطأ | يصف السلوك المعتاد ولا يكشف الذيل وحده |
| زمن الذيل | Tail latency | الطلبات الأبطأ مثل p95 وp99 | المتوسط قد يخفيها؛ يلزم عدد تكرارات وworkload موثق |
| الإنتاجية | Throughput | عدد العناصر في وحدة الزمن | قد ترتفع بالـbatching بينما ترتفع latency الفردية |
| حشو ديناميكي | Dynamic padding | حشو الدفعة إلى أطول تسلسل فيها | يقلل الهدر مقارنة بحشو ثابت طويل عندما تتفاوت الأطوال |
| تجميع حسب الطول | Length bucketing | وضع أطوال متقاربة في batch واحد | يقلل padding مع ضرورة إعادة المخرجات إلى ترتيب IDs |
| تكميم | Quantisation | تمثيل الأوزان/الحساب بدقة أقل | يجب قياس quality tax بعده |
| ONNX | Open Neural Network Exchange | صيغة تبادل للنماذج | ONNX Runtime قد يحسن inference على CPU |
| ONNX Runtime | ONNX Runtime (ORT) | محرك يشغل ONNX graph | الصيغة ليست runtime، والسرعة تعتمد على provider والعتاد والعمل |
| INT8 ديناميكي | Dynamic INT8 | تكميم weights وحساب معاملات activations وقت التشغيل | قد يصغّر artefact لكنه لا يضمن سرعة أو جودة أفضل |
| ضريبة الجودة | Quality tax | جودة baseline ناقص جودة candidate | الموجب انخفاض؛ يقاس على الأمثلة والمقياس نفسيهما |
| قطعة نموذج | Model artefact | ملف/مجموعة ملفات تمثل نموذجًا قابلًا للتشغيل | يسجل hash ونسخة ومعالجة، ولا يلزم رفع الوزن إلى GitHub |
| بيان خدمة | Serving manifest | عقد يربط model وlabels وpreprocessing وruntime | يمنع تشغيل مكونات غير متوافقة بصمت |
| اختبار كناري | Canary test | حالة صغيرة معروفة تكشف انكسار إصدار الخدمة | فشلها يمنع readiness ولا يعوض التقييم الشامل |
| اختلاف التدريب والخدمة | Train–serve skew | اختلاف المعالجة أو labels أو الإصدارات بين المرحلتين | يعالج بوحدة مشتركة وmanifest واختبارات ذهبية |
| مسار رجوع | Rollback path | نسخة/خطوات معروفة للعودة عند فشل candidate | قرار رفض INT8 والاحتفاظ بـFP32 قد يكون صحيحًا |
| واجهة برمجية | API | عقد لإرسال طلب واستقبال نتيجة | نختبر FastAPI داخل Colab بـTestClient |
| عميل اختبار | TestClient | عميل يشغل طلبات HTTP على التطبيق داخل العملية | يثبت العقد بلا استضافة ولا يثبت تحمل إنتاجي |
| جدار التحقق | Validation wall | فصل validation لصناعة القرارات عن frozen test النهائي | يمنع إعادة الضبط على test أثناء اختيار التحسين |
| وسم إصدار | Release tag | اسم ثابت يشير إلى commit مسلّم | يستخدم المشروع `submission-v1.0` لتحديد النسخة النهائية |
| قابلية إعادة الإنتاج | Reproducibility | إعادة النتيجة بإعدادات موثقة | تسجل seed والإصدارات والبيانات والجهاز |
| بذرة عشوائية | Random seed | قيمة تبدأ العشوائية شبه المحددة | بذرة واحدة لا تثبت استقرار فرق صغير |
| بطاقة نموذج | Model card | وصف الاستخدام والنتائج والحدود | توثق المخاطر والسياقات غير المناسبة |
| بطاقة بيانات | Data card | وصف مصدر البيانات وبنائها وحدودها | تشمل الترخيص والتقسيم والخصوصية |
